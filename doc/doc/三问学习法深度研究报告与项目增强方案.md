## 第一部分：三问学习法学术研究

### 1.1 方法论溯源

三问学习法（Three-Question Learning Method）的核心思想可追溯至三大理论源流：

| 理论源流 | 核心主张 | 代表学者 | 与三问法的关联 |
|---------|---------|---------|--------------|
| 苏格拉底提问法 | 通过系统性追问引导学习者自行发现答案 | Socrates, Paul & Elder (2007) | 三问的"追问"本质 |
| 布鲁姆分类学 | 认知过程分为记忆→理解→应用→分析→评价→创造六层级 | Bloom (1956), Anderson & Krathwohl (2001) | 三问对应低→中→高三层认知 |
| 建构主义学习理论 | 知识由学习者主动建构而非被动接受 | Piaget, Vygotsky | 三问的"用自己的话描述"要求 |

### 1.2 三问法的认知层级映射

基于 Anderson & Krathwohl (2001) 修订版布鲁姆分类学，三问法实现了从低阶思维到高阶思维的递进：

```
第一问（描述性）→ 记忆 + 理解（低阶思维 LOTS）
  "请用自己的话描述：{知识点}是什么？"

第二问（分析性）→ 分析 + 评价（高阶思维 HOTS）
  "关于{知识点}，你认为背后的核心原理是什么？为什么？"

第三问（创造性）→ 应用 + 创造（高阶思维 HOTS）
  "你会如何应用{知识点}？请描述一个具体的应用场景。"
```

**关键学术发现**：King (1994) 在《Guiding Knowledge Construction in the Classroom》中证实，**引导性提问比自由讨论更能促进深度学习**，效果提升 23-35%。三问法正是这种引导性提问的结构化实现。

### 1.4 行业实践案例

**案例1：月湖小学"三问导学"模式**
- 实施方式：课前自问→课中互问→课后追问
- 效果：学生自主学习能力提升 40%，课堂参与度从 55% 提升至 82%
- 启示：三问法应贯穿学习全过程，而非仅在单一环节

**案例2：SocraticLM（AI苏格拉底式对话系统）**
- 技术：基于 LLM 的引导式提问，不直接给答案
- 核心机制：6种苏格拉底提问类型自动切换
- 效果：学习深度比直接问答提升 45%

**案例3：DeepTutor（深度辅导系统）**
- 技术：基于布鲁姆分类的自适应对话
- 核心机制：根据学习者认知层级动态调整问题难度
- 效果：学习效率提升 30%，知识保持率提升 25%

## 第二部分：当前应用局限性深度分析

### 2.1 核心问题诊断

经过对代码的逐文件分析，识别出 **6 大核心局限**：

#### 局限1：三问流程线性僵化

```
当前：IDLE → Q1(固定模板) → Q2(固定模板) → Q3(固定模板) → COMPLETED
问题：每个知识点只能走一次，不支持循环深化（Spiral Learning）
缺失：自适应难度调节、追问机制、多轮对话深化
```

- Q1/Q2 需达 60 分才能进入下一阶段，但分数提取使用正则 `(\d{1,3})分`，失败时兜底返回 72 分
- Q3 无分数门槛，只要提交即完成，缺乏对"应用/创造"层次的深度检验
- 问题模板硬编码在 `getPhaseQuestion()` 中，无法根据学习者水平动态调整

#### 局限2：布鲁姆分类法集成浅表化

- `BLOOM_DISTRIBUTION` 仅用于验证测验题分布，不驱动学习路径
- 布鲁姆得分通过简单公式推算（如 `bloomMemory = q1Score * 0.9`），缺乏教育学依据
- 测验与三问流程脱节，测验结果不影响后续学习

#### 局限3：知识图谱仅用于展示

- 图谱由 AI 一次性生成，不支持用户编辑/扩展
- 节点标签截断为 4 字符，信息密度极低
- 不支持学习路径推荐、前置知识检测
- 不订阅 `KP_STATUS_CHANGED` 事件，不会自动刷新

#### 局限4：评价体系深度不足

- Q2/Q3 分数使用 `MOCK_DEFAULT_SCORES`（70/72），并非真实评分
- "错题溯源"仅追踪客观题，三问评价标记为 `'subjective'` 永远无法溯源
- 雷达图仅 3 维度，手动像素绘制，无标签文字

#### 局限5：网络内容爬取缺失

- `WebSearchService` 仅返回搜索摘要，不爬取网页正文
- `MaterialType.AI_CRAWL` 枚举值存在但无实际爬虫实现
- 搜索结果未与知识节点关联，不自动入库
- 点击搜索结果不打开内嵌浏览器

#### 局限6：对话与交互局限

- 单轮问答模式，AI 评价后即结束
- `dialogMessages` 不持久化，切换页面后对话丢失
- `NO_SUBSTITUTE` 约束过于严格，限制了 AI 引导式教学能力

### 2.2 与深度学习系统的差距

| 维度 | 当前状态 | 深度学习所需 | 差距等级 |
|------|---------|------------|---------|
| 认知深度 | 固定模板，单轮评价 | 自适应追问，多轮 Socratic 对话 | ★★★★★ |
| 知识结构 | 静态展示图谱 | 动态学习路径，前置知识检测 | ★★★★☆ |
| 评估精度 | 分数提取粗糙，Mock 分 | 多维度精准评估，学习曲线追踪 | ★★★★☆ |
| 布鲁姆整合 | 仅验证测验分布 | 层级递进引导，认知发展建模 | ★★★★☆ |
| 学习材料 | 用户上传 + 搜索摘要 | 网页爬取解析，多模态资源 | ★★★★★ |
| 间隔重复 | 无 | 基于遗忘曲线的复习提醒 | ★★★☆☆ |
| 个性化 | 统一阈值（60分） | 自适应难度，个性化学习计划 | ★★★★☆ |
| 协作性 | 纯个人 | 同伴学习，社区知识共建 | ★★☆☆☆ |

### 3.2 功能改进详细设计

#### 改进1：自适应三问引擎（核心）

**目标**：从固定模板三问升级为基于学习者认知状态的自适应提问

**设计**：

```typescript
// 新增数据模型
interface AdaptiveQuestion {
  phase: QuestionPhase           // Q1/Q2/Q3
  cognitiveLevel: BloomLevel     // 当前认知层级
  difficulty: number             // 难度 1-10
  template: string               // 问题模板
  followUpTriggers: string[]     // 触发追问的关键词/模式
  scaffoldingHints: string[]     // 支架提示（渐进式）
}

interface LearningState {
  knowledgePointId: string
  currentBloomLevel: BloomLevel  // 当前最高认知层级
  attemptCount: number           // 尝试次数
  scoreHistory: number[]         // 历史分数
  weakDimensions: string[]       // 薄弱维度
  spiralRound: number            // 螺旋深化轮次
}
```

**关键机制**：
- **螺旋深化**：完成一轮三问后，如果 Q2/Q3 分数 < 80，自动进入下一轮深化，问题难度递增
- **自适应难度**：基于历史分数和尝试次数，动态调整问题难度（1-10级）
- **追问机制**：AI 评价后，如果检测到薄弱点，自动生成追问（Socratic questioning）
- **支架提示**：当学习者连续 2 次未通过，提供渐进式提示（从线索到框架到示例）

#### 改进2：Socratic 追问引擎

**目标**：实现苏格拉底式多轮对话，引导学习者自行发现答案

**6种追问类型**（基于 Paul & Elder 框架）：

| 类型 | 目的 | 示例问题 |
|------|------|---------|
| 澄清 | 确保理解准确 | "你说的'核心原理'具体指什么？" |
| 探究假设 | 挑战隐含前提 | "你得出这个结论的前提是什么？" |
| 探究理由 | 要求证据支撑 | "有什么证据支持你的观点？" |
| 质疑观点 | 引入不同视角 | "有没有人持不同观点？为什么？" |
| 探究后果 | 推演逻辑结果 | "如果这个原理成立，会导致什么结果？" |
| 元认知 | 反思思维过程 | "你是如何得出这个结论的？" |

**实现方式**：
- AI 评价后，分析学习者回答中的薄弱维度
- 选择最合适的追问类型（基于规则 + AI 判断）
- 追问不重新计分，但记录在对话历史中
- 最多 3 轮追问，避免认知过载

#### 改进4：布鲁姆认知发展建模

**目标**：从简单分数推算升级为基于认知发展理论的精准建模

**设计**：

```typescript
interface CognitiveProfile {
  knowledgePointId: string
  bloomScores: Map<BloomLevel, number>   // 六层级独立评分
  cognitiveTrajectory: CognitivePoint[]   // 认知发展轨迹
  zoneOfProximalDevelopment: BloomLevel   // 最近发展区
  recommendedNextStep: string             // 推荐下一步行动

  timestamp: number
  bloomLevel: BloomLevel
```

**关键机制**：
- **独立评估**：每个布鲁姆层级独立评分，不再用公式推算
- **认知轨迹**：记录每次评估的时间戳、层级、分数和依据，形成学习曲线
- **最近发展区（ZPD）**：基于 Vygotsky 理论，识别学习者当前可达的最高认知层级
- **层级桥接**：从"理解"到"应用"的过渡提供脚手架问题

#### 改进5：间隔重复调度引擎

**目标**：基于遗忘曲线实现知识点的科学复习

**算法**：SM-2 变体（SuperMemo 2 算法改编）

```typescript
interface ReviewSchedule {
  knowledgePointId: string
  easeFactor: number       // 难度因子 (1.3-2.5)
  interval: number         // 复习间隔（天）
  repetitions: number      // 已复习次数
  nextReviewDate: string   // 下次复习日期
  lastReviewDate: string   // 上次复习日期
}

// SM-2 核心逻辑
function calculateNextReview(quality: number, schedule: ReviewSchedule): ReviewSchedule {
  // quality: 0-5 (0=完全遗忘, 5=完美记忆)
  if (quality >= 3) {
    if (schedule.repetitions === 0) schedule.interval = 1
    else if (schedule.repetitions === 1) schedule.interval = 6
    else schedule.interval = Math.round(schedule.interval * schedule.easeFactor)
    schedule.repetitions++
  } else {
    schedule.repetitions = 0
    schedule.interval = 1
  }
  schedule.easeFactor = Math.max(1.3, schedule.easeFactor + (0.1 - (5 - quality) * (0.08 + (5 - quality) * 0.02)))
  schedule.nextReviewDate = addDays(schedule.lastReviewDate, schedule.interval)
  return schedule
}
```

```sql
    FOREIGN KEY (course_id) REFERENCES course(id),
    FOREIGN KEY (knowledge_node_id) REFERENCES knowledge_node(id)
)
```

**关键机制**：
- 每次对话消息持久化到 `dialog_history` 表
- AI 评价时加载最近 10 条对话作为上下文
- 支持对话回放和笔记标记
